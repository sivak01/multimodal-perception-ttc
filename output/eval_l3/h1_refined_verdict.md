## Limitations

- Composition ("merged" vs "single") is derived INDEPENDENTLY of the fused tracker's own `is_multi_sensor` bookkeeping: it counts how many of the three solo single-sensor trackers (lidar/radar/camera_mono, same CentralTracker class, run separately) had a candidate within MATCH_DIST_THRESHOLD_M of the real object at that exact sample. This avoids the whole-track-lifetime forward-looking bias a track-level flag would introduce (a track that becomes multi-sensor LATER would otherwise be labelled "merged" even at an earlier, still-single-sensor instant).
- The in-corridor check uses ego's own BODY heading (yaw, from each sample's real ego_pose rotation quaternion), not its velocity heading -- see ego_heading.py.
- class_group/odd/motion can be undefined for a given row (e.g. a GT instance whose category or speed could not be resolved); such rows are excluded from the relevant supplementary stratification slice only, not from the main (a)/(b)/(c) analyses.
- All thresholds (config_l3.py) are ASSUMED, fixed before any result was computed, and were not tuned after seeing these numbers.
- Scene-level bootstrap: 2000 resamples, seed 42, 95% CI, resampling the 85 real scenes present in this dataset with replacement -- not individual rows -- per this session's own rule 4.
